# Traffic Pattern Analysis — Day-1 Solo Work

Honest, leakage-safe hourly traffic forecasting built on day one, before the team
switched plans. Documents the effort and the real numbers the approach achieved.

## Layout
- `src/pipeline.py`   data loading, weekly climatology, features, LightGBM ratio model,
                      split-conformal 90% intervals, peer-group cold-start fallback
- `src/gnn.py`        numpy GCN for cold-start stations: level interpolation over the
                      road network, peer-group hourly shapes, hand-derived backprop
                      with a numerical gradient check
- `src/metrics.py`    MAE, RMSE, R2, WAPE, GEH, coverage, Winkler, %within, gap-to-ceiling
- `src/scenarios.py`  scenario estimation method (illustrative; official prompts were not supplied)
- `run_pipeline.py`   runs the backtest, writes the validated submission, saves artifacts
- `viz/*.py`          one script per figure -> outputs/figures/*.png (seven figures)
- `experiments/`      the cold-start ablation sweep behind the "dead ends" section below
- `Day1_Showcase.ipynb`  displays and explains the figures (no heavy compute; the
                      headline table is read from `outputs/metrics.json`, not typed in)
- `day1/`             the supplied participant files (inputs)
- `outputs/`          metrics.json, submission.csv, scenario_results.csv, artifacts.npz, figures/

## Reproduce
```
pip install -r requirements.txt
python run_pipeline.py                 # reads ./day1, writes ./outputs
cd viz && python fig1_daily_profile.py # ...and the rest
```
`day1/` must hold `traffic_train.parquet`, `traffic_validation.parquet`, `network.csv`,
`network_edges.csv`, `submission_template.csv`, `scenario_template.csv`.
`DATA_DIR` and `OUT_DIR` override the input/output folders. Paths resolve against this
file, so the run works from any working directory. Open `Day1_Showcase.ipynb` for the story.

Everything in `outputs/` is regenerated by that command; no metric is typed in
anywhere. If you change the code, re-run before trusting the figures.

## Honest headline (backtest: fit 2024, score H1 2025; offset left as on day one)
Seen series (LightGBM), 556,800 scored rows:

| metric | value |
|---|---|
| MAE | 302 veh/hr (seasonal naive 308) |
| RMSE | 509 |
| R2 | 0.720 |
| WAPE | 0.392 (naive 0.400, oracle ceiling 0.133) |
| MAPE | 85.5% |
| GEH < 5 / < 10 | 31.4% / 53.9% |
| 90% interval coverage | 90.0% against a 90% target |

Cold-start (GCN), estimated by holding out 15 stations with known history and
predicting them as if they had none — 112,560 rows:

| metric | value |
|---|---|
| WAPE | 0.546 (naive global mean 0.686, so 20% better) |
| MAPE | 116.7% |
| GEH < 5 / < 10 | 24.7% / 46.8% |

Delivered file: 170,956 rows, 120,571 routed to LightGBM and 50,385 to the GCN.
`run_pipeline.py` asserts the submission invariants (row count, no NaN/inf,
lower <= forecast <= upper, reliability in [0,1]) before writing.

The same method with the later +2h offset fix reaches roughly MAE 114 / WAPE 0.148 —
the fix was a data correction, not a model change. Pass `apply_offset=True` to
`load_all` to see it.

## Notes
- No leakage: features use only information available at prediction time, and the
  cold-start holdout hides the held-out stations from the peer shapes and level
  priors as well as from the GCN loss.
- Cold-start stations are filled from the GCN level blended with a peer-group median,
  with wide intervals and a low reliability score.
- `reliability_score` is derived from this run's measured accuracy (1 - WAPE per path,
  with a night-hours haircut), not asserted.
- Cold-start intervals are calibrated on the holdout's actual/predicted ratio
  quantiles rather than treating a mean absolute error as a standard deviation.
- Scenario results are illustrative estimates; the official prompts were never in the
  bundle. All five template scenario ids are always answered.
- AWS (S3, Bedrock chatbot, QuickSight) is separate and not part of this package.

## Measured dead ends (kept here so they are not retried blindly)
Reproduce the sweep behind this section with `python experiments/ablate_cold_start.py`.
It toggles four choices independently on the 15-station cold-start holdout and prints
the WAPE for all 16 combinations; the first row reproduces the original 0.539.

- **Weighting graph edges by `edge_type` / `distance_band`.** The obvious use of those
  two columns. Measured on the holdout it is much worse: cold WAPE 0.55 -> 9.5, with
  predicted station levels diverging to a mean of 874,000 against a true ~700.
  Down-weighting neighbours raises the self-loop's share of the normalised adjacency,
  and because each node is fed its own level, the GCN learns to read its own answer
  instead of interpolating. Fixing it needs the level channel separated from the
  self-loop, not a weight on the edge.
- **Widening the feature sets.** Adding `surface_type`, `lane_width`,
  `roadway_width_band`, a blank-class flag and an AADT-based class imputation:
  no MAE/WAPE gain for LightGBM, and clearly worse for the GCN (cold WAPE
  0.55 -> 0.65) — 60-odd training nodes cannot support the extra width.
- What did help: grouping cold-start stations by `functional_class` **falling back to
  `aadt_band` when it is blank** (28% of stations, which previously all collapsed onto
  one global hourly curve). Cold GEH < 5 improved 22.8% -> 24.7%.
